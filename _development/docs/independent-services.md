# 输入记录与连携图像识别

两项服务独立于 Npcap、密钥和伤害分析。首页以独立卡片显示两项状态，输入记录可在首页启停；连携识别只在悬浮窗页启用，首页提供导航。抓包启停不停止它们。
先在设置中指定实际 `Endfield.exe`。程序按进程路径识别目标，不按窗口标题猜测。

## 输入记录

首页「开始记录输入」启用独立子进程，启动默认关闭；设置中的「启动时记录输入」独立保存，默认关闭，手动启停不改变此选项。只记录游戏前台期间的输入；
切出、设备断开、停止或日志换文件时写入中断，重新进入时保存按住状态基线，不伪造按下。
普通权限 GUI 启用输入记录时，仅记录子进程通过 Windows 授权申请管理员权限，主 GUI 和其他服务不提权。取消授权明确显示输入记录失败，不静默回退为已启动；GUI 本来已是管理员时直接启动记录器。
普通权限中继使用单次随机凭据认证本机命名管道，只转发状态、trace 轮换和停止命令；键鼠事件仍由记录器直接写盘，不传给 GUI，不增加网络端口。控制连接断开后记录器结束并关闭文件。日志目录先由普通权限中继创建，避免输入日志因目录权限而无法读取。
键鼠采用 Windows Raw Input，手柄采用 SDL3，保留设备身份、原始键码、轴值和映射关联；采集不应用绑定或死区。
当 Windows 未投递对应 Raw Input 报告时，使用被动键鼠事件兼容采集；有 Raw Input 报告时优先采用，避免重复。兼容事件标为 `windows_hook`，设备身份不可用，鼠标移动为屏幕绝对坐标，文件中记录切换诊断，不伪装为逐设备原始数据。两种路径均只写入游戏前台的输入，不屏蔽或注入操作。
Windows 消息接收有独立线程，不在回调中执行进程发现、SDL 初始化或写盘。原始报告及事件回调都未送达时，以 `windows_state` 标注前台状态采样（8ms），保留实际采样时间及精度；状态采样在录制进程控制循环中执行，与钩子消息线程分开。不能还原自动重复、滚轮、原始鼠标位移或短于采样间隔的点击。事件报告优先，钩子收到时立即通知去重，再等待原始报告优先发布，避免与采样重复。
独立写线程批量写盘，持续繁忙时也每 250ms 刷新文件缓冲；队列有界，溢出写明缺失区间，故障只影响输入服务。
首页直接显示键盘、鼠标输入和缺失计数，文件元数据不算按键。悬停提示补充文件记录总数、前台事件及原始报告计数，不包含具体按键；原始报告读取失败会显示故障。每 5 秒写入 `input_backend_health` 诊断，区分消息线程是否推进、状态采样次数、收到的原始报告和前台过滤数量。

抓包正在写 trace 时生成同名 `.input.jsonl`，中途重开为 `.part-时间.input.jsonl`；
没有抓包时在同一日志根目录的 `YYYYMMDD` 子目录生成 `input_日期.input.jsonl`，与默认 trace 所在目录一致。文件为版本化 JSONL，含系统/单调时钟、序号、设备、焦点、异常与结束记录。
开始抓包或 trace 换文件时会关闭上一份输入文件，后续事件写入新 trace 的配套文件。手动绑定应选覆盖战斗时间的文件；绑定本身不会追随录制文件轮换，也不会自动替换用户已选的文件。
结束时可用 trace 前缀 SHA-256 校验关联，不改 trace 或其完整性文件。原始输入文件可能包含私人操作，请自行保管；Git 和打包均排除它们。

战斗分析可自动发现同名配套文件，也支持「绑定 input log」。每场战斗保存独立绑定、对齐及槽位设置，路径相对 trace 保存；「显示输入」单独控制是否绘制，绑定、解绑都不改变显示开关。后台仅索引选中记录，重绘复用缓存。
解释设置可修改组合键、动作、角色槽位、短按/长按和阈值；默认 280ms 只是参考值。
更具体组合优先，自动重复不产生新动作，已长按不再生成短按。多设备输入不会拼成一个组合。
战技/终结技按输入时刻的 trace LOADOUT 槽位归属；缺证据显示槽位，可手动补充。连携保持全局，不猜角色。

两种分析风格共用同一解释结果：蓝实线战技、橙实线终结技、紫虚线全局连携，同色区间表示按住过程；
中断使用虚线边界，悬停查看规则、设备和时长。其他按键、鼠标移动、模拟量默认隐藏，可在解释设置开启。
系统时间对齐不补偿抓包延迟、不吸附技能点，也不随时缓/时停移动。分析结果的起止日期保留毫秒；旧快照优先复用已有的毫秒级计时观测。绘图区只覆盖所选战斗的 `0..duration_ms`，输入文件和 trace 的其他时段不扩大范围；跨边界的按住区间按本场范围裁切绘制，悬停仍保留原始起止时间。旧日志日期不明可手动指定起点与偏移。
绑定栏分别显示本场原始输入数量与解释后的动作数量，悬停可对比整个文件的输入分类；绑定成功但战斗范围没有输入时直接提示检查录制和对齐，不将零动作误称为绑定失败。未结束的录制文件仍可读取。
输入表示操作意图，不证明技能成功；既有技能块、伤害、rDPS 和上传内容不变。
trace 重命名会事务性处理配套文件并更新绑定，列表移除不删磁盘文件。最近输入 Overlay 暂停维护，入口与自动分发已关闭，不影响录制和历史输入轨道。

## 连携 CD

悬浮窗页启用「连携 CD」，多个订阅者共用一套捕获和识别。显示/隐藏与功能启停分开；隐藏仍识别，最后一个订阅者停用时释放捕获资源。
窗口捕获使用 `QWindowCapture → QMediaCaptureSession → QVideoSink`，明确选择 FFmpeg / `uwp`（WGC）；不可用时单独提示，不切换为 GDI。
游戏重开重新发现 HWND。多窗口可在「连携识别设置」选目标；自动判断键鼠、手柄及组合键布局，不可靠时框选四个槽位的冷却条、血条和阵亡图标。
坐标相对游戏客户区/黑边后的画面，与浮窗坐标和尺寸无关。预览只在设置窗口打开时转换整帧，不保存截图。
非 16:9 画面同时核对等比缩放、左下锚定的 HUD 候选，预览框跟随实际选中的区域。灰色背景不能单独证明存在冷却条；条首边框不计为未填充，无法确认时显示待校准。

最高 20Hz，捕获/识别在工作线程，仅保留最新待处理帧和最新结果。普通路径映射画面后只复制小区域；Qt 后端自身仍有整帧纹理复制开销。
成功识别的当前状态立即替换旧状态，不要求先见到空条或再等一帧。明确亮前缀/暗后缀属于冷却证据；只定位到血条、但冷却条均匀变暗或形状不明确时属于识别失败，才延续旧状态。已确认布局允许单个可读槽位独立更新，其余槽位各自保留旧状态。低血量及染色 HUD 分槽判断；新布局至少需要三槽支持，避免两个零散背景色块建立错误布局。剩余秒数用近期稳定填充速度估计，有效观测出现停滞/跳变时清除估计。
运行日志每 10 秒记录各槽可读性、进度、就绪/消耗证据与候选布局；不保存游戏画面，也不因为诊断变化重复刷新浮窗。
暂时不可读时沿用上次可信状态；已有可靠秒数则按其速度继续估算，到零后保持 CD 就绪，直到新的有效识别修正。没有速度证据则只保留原进度，不编造秒数。就绪时整行变绿。未识别过的槽位仍显示未知，捕获目标或已确认布局/尺寸改变时重新确认。低血量本身不表示阵亡。
相同展示状态不重复发布；进度更新不重新测量窗口布局；无目标或持续无效画面降低检查频率。前端只显示服务端状态，不自行计时。

无抓包也显示位置 1–4；当前实时队伍事件按槽位补姓名/头像。停止抓包、会话/目标变化清身份，历史记录不覆盖实时身份。
模板提供四圆图标和四行进度条，切换时自动调整窗口宽高。进度条宽度可独立拉伸，只有高度变化才缩放文字、头像及条高；独立字体/头像比例仍生效。设置和尺寸保存后重开保持。`combo_snapshot` 为 schema 2，含 stream/sequence、有效性及四槽的观测进度和可空估计值；前端不自行倒计时。
此消息只通过进程内桥分发，未新增端口，也未恢复抓包服务中的旧连携计时。

## 环境与验证边界

开发环境通过 `Setup-Dev.cmd` 或 `python -B _development/tools/prepare_native.py` 按清单恢复 SDL3，支持 `--archive` 离线提供官方 ZIP。
便携包共用一份 SDL3，保留 QtMultimedia、FFmpeg 媒体插件及依赖闭包，不加入 MultimediaWidgets 或额外 OCR/OpenCV。
运行库缺失只禁用对应组件；历史分析、主 GUI 和其他服务继续可用。

合成测试与自有 Windows 动态窗口用于验证输入解释、队列、状态机、WGC、GUI 生命周期与 DOM 链路，不能替代游戏实战识别率。
没有实体 Xbox/DualSense、无线/独占连接或相同实战录像的验证时，应明确保留为未验证组合。
主要维护入口见 [源码导航](../../_internal/src/README.md)；测试为 `python -B _development/run_tests.py app-independent`。
