# trace 导入与贡献口径

战斗日志页批量导入本地 .log，只引用原文件，不复制或改写。首次建立分场索引，
完整分析在点击加载后于后台执行。Ctrl / Shift 多选、全选可批量加载；
浮窗仅显示最后选中的战斗，不合并场次。“返回实时日志”恢复实时。

列表移除只隐藏记录，不删除文件。重命名修改实际文件名，并同步 status/完整性旁文件、
索引及打开中的详情；保留 trace 前缀、日期与扩展名。正在写入的文件须先停止抓包。
“打开所在文件夹”定位最后选中文件。外部改动文件后要求重新索引。

新采集的 `trace_*.log` 与 `.log.status.json` 可直接交给**官网版 uploader** 的自动归档入口，
不需导出转换版。`launcher.log`、`session_*.ndjson` 不能代替 trace。
status 是归档门禁上下文，不是通用完整性 proof；旧日志、损坏证明及后端校验仍可能拒绝。
参见 [外部资源](runtime-resources.md)。

## 通用腐蚀

补充 `buff_common_natural_fire_triggered`（329）动态减抗批准；来源读取 trace，
不硬编码为诀。只读取实际 def_decrease / additional_def_decrease 和对应实例属性刷新证据，
不积分 tick，也不按本次 start/max 钳制继承状态。try/wrapper 不重复记账。
抗性反事实及跨乘区 ln 分配不变，证据不足时保守标记。

## 祀笔意

`parser_core/ink_provenance.py` 按实例、会话和目标隔离账本，匹配记录时的原命中。
发射时冻结，清空不影响已发射爆炸；按实际 HP 损失缩放并保持总量守恒。

开发版口径 `whole_ink_damage_log_zones_v1`：实际记录比例 r 形成祀的独立乘区 1+r，
每笔爆炸全部伤害按 ln(1+r) 与原命中已识别外部辅助乘区对数权重分配，不预留基础份额。
原伤害120、辅助×1.2、记录10%、爆炸12时：祀约4.1196、辅助约7.8804。
原命中本身不重复记账。这是开发版约定，不宣称官网使用同一政策。

未配对累计、未验证分支、嵌套笔意或原命中条件缺口保持质量未解决状态，不补猜来源。
普通回归使用合成协议数据，真实战斗和账号信息不入库。
