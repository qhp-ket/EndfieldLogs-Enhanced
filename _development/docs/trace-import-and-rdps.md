# trace 导入与贡献口径

## 历史记录

战斗日志页引用原文件并建立分场索引，加载时后台完整分析。Ctrl/Shift 多选及全选可批量加载，浮窗显示最后选中的战斗。
「返回实时日志」恢复实时来源，「打开所在文件夹」定位最后选择。

列表移除只移除引用。重命名事务同步 trace、status/完整性旁文件、input log、绑定及索引，保留 trace 前缀、日期和扩展名。
正在写入的 trace 先停止抓包；文件外部变更后重新索引。

`trace_*.log` 及 `.log.status.json` 可直接进入官网 uploader 自动归档，上传还需完整性证明和官网校验。
组件准备见 [运行资源](runtime-resources.md)。

## JSONL 连续记录

新录制默认使用 JSONL，规范化业务事件直接进入实时分析；显式配置 `service.trace_format: "legacy"` 仍沿用旧格式。历史页可导入新 trace 或读取配套 session，按需分析沿用同一计算核心，无须先转换为旧文本。

GUI 启动默认未记录。首页「伤害日志」的「开始／停止记录」或 `Ctrl+I` 同步启停 session、trace 及启用的输入侧录；每次开始创建新文件组，停止写完缓冲并关闭文件，实时分析继续运行。历史按录制身份连读已有连续分卷，缺卷时提示记录不完整；请将配套文件保留在同一目录。

JSONL 不能直接交给官网 uploader。先在历史页选择一场，点击「导出官网兼容日志…」生成旧 `.log`；多选时只导出最后选择的那场。保留该场伤害、计时和必要前文，不带入其他场次；session 导出会重新确认该场边界，纳入同场新写入的证据。导出器按最终正文生成完整性证明，原 JSONL、session 和输入侧录保留。录制中的 session 正常追加不影响已有固定范围的重放；已索引内容改写、截断或缺卷仍拒绝处理。

JSONL 历史分析与导出共用 `history/structured.py::structured_record_events`，补入原有上下文保留规则选出的角色、敌人属性等前文，不带入前场伤害。session 使用 `history/analysis.py::session_record_events`；回放基准日取首个回放事件在录制时区的日期，记录身份仍使用首击的完整 Unix 时间。

兼容正文只有时分秒。单场导出将首条实际输出事件的录制本地日期保存为文件修改日期，供重新导入使用；界面统一调用 `history/export.py::default_battle_export_path`，默认名 `trace_战斗N-官网兼容.log` 不携带源录制日期。旧文本导入优先取文件名中的 `YYYYMMDD`，因此不能将源录制日或首击日直接用于默认命名。回归覆盖跨午夜计时、次日后续战斗、JSONL／session、东八区／西五区、界面默认路径及其他场次隔离。

## 通用腐蚀

`buff_common_natural_fire_triggered`（329）的动态减抗来源取 trace 实例，读取实际 `def_decrease` / `additional_def_decrease` 及属性刷新证据。
继承状态按实例保留，try/wrapper 去重记账；反事实抗性与跨乘区 ln 分配沿用核心规则，缺证据时标记待确认。

## 祀笔意

`parser_core/ink_provenance.py` 按实例、会话和目标隔离账本，关联记录时的原命中。
发射时冻结记录，已发射爆炸独立保留；按实际 HP 损失缩放并保持守恒。

项目口径 `whole_ink_damage_log_zones_v1`：

- 实际记录比例 r 形成祀的独立乘区 `1+r`。
- 每笔爆炸按 `ln(1+r)` 与原命中外部辅助乘区的对数权重分配全部伤害。
- 例：原伤害 120、辅助 ×1.2、记录 10%、爆炸 12，祀约 4.1196、辅助约 7.8804。

原命中采用自身一次记账。未配对累计、未验证分支、嵌套笔意或条件缺口保留质量未解决状态。
该分配为本项目约定；官网使用其自身实现。普通回归使用合成协议数据。
