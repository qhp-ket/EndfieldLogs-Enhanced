# Endfield Logs - Enhanced 便携包

目前没有 i18n，界面和说明以中文为主。
实时链路为 Npcap 被动抓包 → 本进程解码 → trace → 增量贡献计算 → 轻量摘要 → 浮窗；
本地分析按需从 trace 生成完整报告和时间轴，上传使用单独发行的官网 uploader。
程序不向游戏进程注入、Hook 或读写内存；登录解码在本程序进程内调用本机游戏 DLL 的导出函数。

适用于 Windows 10 / 11 x64。请先完整解压 ZIP 到有写入权限的目录，再双击
`Start-GUI.cmd`。包内附带 Python 3.14、Qt / WebEngine 及程序依赖，无需另装 Python，
无需 pip，GUI 通过包内 Python 启动。

## 第一次使用

1. 实时抓包需要安装 [Npcap（官方下载安装页）](https://npcap.com/#download)。缺少 Npcap 时仍可导入、分析本地 trace 日志。
2. 关闭其他抓包客户端，运行 `Start-GUI.cmd`，在「设置 → 游戏路径」选择 `Endfield.exe` 或游戏目录。
   游戏迁移或重装后，可在同一位置重新选择；修改后下次启动抓包生效。
3. GUI 默认不开始抓包，准备好后点「启动抓包」，再启动游戏；设置中可开启「启动时开始抓包」。
   主动停止后不会自动重启；停止后再启动需要重开游戏，不能接续已有会话。
4. 悬浮窗页可开关窗口、设置字体和尺寸，卡片右上角可重置尺寸、字体和位置。
5. 战斗日志页可导入本地 trace，加载后查看分析、发送到伤害浮窗，或返回实时日志。
   战斗分析顶部可在 Qt 和官网风格（本地）两种界面间切换。

伤害浮窗和战斗分析支持可关闭的离线角色头像。
连携 CD 在悬浮窗页启用，使用图像识别，无需 Npcap；抓包仅补充角色身份。识别设置可预览并手动校准四个位置。
首页可独立开始/停止输入记录，启动默认关闭；设置中可单独开启「启动时记录输入」。仅游戏 EXE 位于前台时记录键鼠和手柄，原始文件为 `.input.jsonl`。
普通权限启动时，仅输入记录子进程申请管理员权限；取消授权不影响其他功能。
有 trace 时生成配套输入文件，无抓包时也可独立录制；历史分析支持自动发现或手动附加，并可调整绑定与对齐。
开始抓包或 trace 换文件后，输入记录也会切换到对应的 `trace_*.input.jsonl`；手动绑定时请选择覆盖该场战斗时间的文件。
长按默认 280ms 是参考判定值，输入意图不代表成功释放。输入文件不交给官网 uploader。
连携就绪时整行变绿；识别暂时中断时沿用原状态，已有估计秒数继续计时，到零保持就绪，等新识别修正。CD 就绪不代表满足触发条件。
设置中的「关于」可检查正式版更新；启动时默认后台检查，只提示版本号、发布日期与下载页，不自动更新文件。

在终端执行 `Start-GUI.cmd --check` 可检查依赖和 Npcap；此命令不会开始抓包。
解压路径可以包含空格和中文。不要直接在压缩包预览窗口里运行。

## 日志与上传

个人配置、缓存、日志和历史列表都在解压目录下的 `.dev-gui/`，首次运行自动生成。
本包不包含打包者的个人配置、账号、日志或历史记录。转发给其他人时，请发送原始 ZIP，
不要直接压缩自己已运行过的整个目录。

官网原版独立 uploader 另行打包，主程序包不包含它；本地分析和 Overlay 无需下载 uploader。
上传时单独解压 uploader 包，运行其中的 `Uploader/EndfieldLogsUploader/EndfieldLogsUploader.exe`。
它自带运行依赖，可以放在任意目录；也可将整个 `Uploader/` 文件夹复制到主程序根目录。
选择 `.dev-gui/logs/battles/` 日期目录中的 `trace_*.log`，并保留配套的
`.log.status.json`。本程序新采集的 trace 可直接交给官网版 uploader，无需转换。
`session_*.ndjson` 与 `launcher.log` 不是可上传战斗 trace；上传仍需官网账号与服务器正常接收。
